Waypointer hub and tracking

The main window owns selection, frame and native window lifecycle. Each section is a reusable content panel; switching sections preserves its current filters. Edit previews are cleared when leaving the waypoint editor. All global configuration preferences live in SETTINGS; record styles and list filters stay beside the records they affect.

Editor focus activates only the attached owning hub. Native HeadsUpDisplay.setActiveWindow registers its argument as a top-level component, so a child content panel must never be passed directly. Closing removes every owned HUD component, including cached panels promoted by older focus code and dropdowns registered in both native popup and component lists. Filter windows are disposed through their original HUD. Preview cleanup errors cannot prevent removal; unrelated windows and navigation remain active. The native lifecycle regression covers route/close, compass reopening, editor typing, chat-focus restoration, legacy orphan removal, auxiliary filters, failed preview cleanup and HUD replacement.

Search

ALL WAYPOINTS has server, user, type and status selectors, with no + filter or - filter text rows. Other searchable sections retain both text filter rows with the same layout: caption, text field and Clear button on one 28 px line, with examples in hover hints. Each comma-separated fragment is a literal substring, not a regular expression. horse, wolf includes either name; old, champion excludes either fragment even when plus matches. Matching is case-insensitive. Surroundings also searches category, material, modifiers, deed state and IDs. Deed search covers the displayed deed, mayor and coordinates.

Position states

Catalogue membership alone never adds a managed object to ALL WAYPOINTS. Press Track in VEHICLES or MY ANIMALS, press Nav for an animal, or explicitly add a nearby object as a waypoint, to include it. Added targets may later have unknown positions without losing their place in the list.

Waypoint membership is persisted independently of On/Off. Disabling an added target hides its marker but retains the row. Delete in ALL WAYPOINTS removes membership and disables tracking immediately; catalogue refreshes and movement keep it outside the list until another explicit Track. Its catalogue entry and coordinate history remain available. When loading an older cache, enabled targets are retained as added while automatic disabled candidates stay outside the list.

| State | Meaning | Presentation |
| --- | --- | --- |
| Visible now | Coordinates received from a currently streamed target | Live marker and navigator follow movement |
| Last known position | Target left the stream; the previous coordinate was retained | A grey compass marker with the state and observation age; NAV goes to that saved place |
| Position unknown | Catalogue entry without coordinates or an expired position | Animal Track starts a waypoint race using native Find; Nav restarts it after stopping |
| Approximate direction | Native animal Find returned a relative sector and distance band | Bearing uncertainty remains available in the hint; animal Nav starts a search |
| Animal search point | Temporary destination computed from the latest direction response | Marker and route guide the next search step; this point is not saved as an animal sighting |

Confirmed creature death removes its waypoint and saved tracking entry, stops NAV and cancels any animal search. The native creature-to-corpse event and confirmed death-animation removal both trigger cleanup. Late updates during the death animation cannot restore the creature in Surroundings. The corpse has its own object ID and does not inherit the waypoint. Merely leaving the client stream keeps the last known position.

MY ANIMALS requests the vanilla Manage animals catalogue on first selection. VEHICLES separately requests carts/wagons and ships. Refresh requests the selected catalogue again; switching back preserves its data without repeating requests. Both views use 28 px table rows with fixed branded Bold headings, shared column geometry and compact grouped actions. All headings cycle ascending, descending and source order; missing distances/timestamps stay last in both directions. Background revisions preserve existing row order, the visible UUID and its intra-row pixel offset. Bearing/range uncertainty is retained in semantic hints rather than embedding a plot in every row. Native BML backslashes are literal text, including the ascending Name /\ heading. Owned recognized responses populate Waypointer; manual or unknown forms remain native. Track automatically starts a waypoint race for an animal outside the client stream when the native animal catalogue supplies Find and a valid creature ID. The separate Direction button has been removed; Nav can restart the search after stopping. The ID may come from a radio selector or a nested native care, brand or tame button; reading it never executes that action. Refresh discards legacy row-number placeholders. Visible targets are matched by ID, including observations received during tracking-cache startup. Rows without an ID remain readable but cannot be tracked. The gateway sends only close or find responses; it never invokes care, brand, tame, transfer, hitch, lock or other ownership actions.

Readings use the character's pose at the Find request. Up to four readings no older than one minute are intersected; the result remains an approximation because animals can move. Bearings expire after two minutes; the earlier exact last coordinate is restored when available, otherwise the position becomes unknown. Last coordinates are retained for 90 days by default, configurable in SETTINGS. Clear last seen removes the saved coordinate; Untrack removes waypoint membership while preserving its history. Refresh can repopulate a cleared coordinate when the client receives the target again.

Animal Nav enables tracking automatically. A currently streamed animal receives ordinary navigation immediately. Otherwise the waypoint race requests Find, projects a search destination along the reported direction and distance band, and routes there. When the player is strictly less than 10 tiles from that point, it requests another reading and moves the destination. Only the latest reading determines each step because animals can move. When the animal enters the client stream, navigation switches to its received coordinates and the race stops checking. Stop, Untrack, another navigation target or disconnect cancels the race. An unavailable direction stops it immediately; three unanswered requests stop it with a message. Search destinations are session-only and never overwrite saved exact sightings.

The former friends section and native friend tracking are removed. Legacy tracked player records are discarded when loading the dynamic catalogue.

Settings and persistence

The full-map toolbar includes ALL MAPS ON SERVER. It opens the five-map gallery even after the current surface finishes loading. Select Liberty, Novus, Caza, Infinity R5 or Old Infinity to view its published image; wheel zoom and dragging work on the selected map. CENTER restores the connected world's viewport and centers your character. Browsing another continent does not change server identity, the mini-map, navigation or saved data. Each selected map displays its own deeds and roads. DEEDS and ROADS toggle the browsing layers independently of the connected mini-map. Live terrain, player/waypoint overlays and waypoint creation remain limited to the connected map. The gallery reuses bundled miniature images. Selecting another continent downloads its full published surface, deed catalogue and highway network on separate background services, with validated atomic caches and the configured refresh intervals. The miniature remains visible during loading. Remote loading and synchronization start only when the user opens that continent; leaving for the gallery or home map, or hiding the full map, cancels its refresh. Reopening uses the validated cache and refreshes that continent. The connected deed provider, navigation highway network and live observations stay on their own world.

The hub enforces the minimum width required by every section at the selected language and font size. Its tables have only vertical scrollbars, with headings fixed above the scrolling body. Monitoring uses whole rows and an 8 px minimum gap before its footer; active Mark/Clear actions stay green until cleared. MOBS AROUND uses Mark, Name, Condition, Hostility, Unique, Deed and Distance. Condition is the creature modifier; Hostility is the received native attitude. The unavailable Traits column is removed. All column headers cycle ascending, descending and original arrival order; the separate sort dropdown and Apply action are removed.

Surroundings actions occupy a compact footer. ADD TO MONITOR is a normal 28 px action in the summary above the fixed table header. The seven translated section selectors share a 16 px High density font in one top toolbar. Text filters use single lines with examples in their hints. Table rows are 28 px; their 24 px actions retain 2 px of non-clickable space above and below. Ordinary text stays at 16 px. The standard opening size is 1120 × 480 px, widened only for actual localized column requirements. Chamomilo updater 1.2.6 supplies the sole embedded UI SDK 0.4.9, verified in the JAR and ZIP.

Language codes are en, pt-BR, de, ru. Names received from the server are not translated. A settings draft applies only after the full draft validates and the background save succeeds. Comments, unrelated properties and a .bak copy are preserved. Storage path changes take effect after restarting the client. Existing settings and existing waypoints remain compatible.

The dynamic target file is wurm-waypointer-data/dynamic-targets.wpt. Its records are qualified by character and endpoint. Restart converts previously live coordinates to last known coordinates. A failed cache load disables writes to preserve the unread file and reports the problem in the catalogue view; a failed save is reported and retried. Main static waypoint storage remains separate.

Architecture and verification

- core: tracking state, bounded BML parser, direction geometry, filters, localization and settings schema. No native rendering or network requests.
- client-wurm: Manage transport and request ownership/timing, vanilla friend adapter, streaming integration, background storage/settings adapters and hub panels.
- render-wurm: shared button/frame resources and navigation projection. Last known and exact positions use distinct presentations; bearings never enter exact navigation.

Tests cover valid/unknown/truncated native forms, unsolicited replies, owner mismatches, fresh question IDs, manual Manage cancellation, timeouts, failed replies, substring precedence, restart/account/endpoint isolation and comment-preserving configuration saves. The native UI probe uses production Wurm layout/input components with GPU drawing replaced by an offscreen renderer and emits previews for all seven views in all four languages. It also checks keyboard-focus queries and native selector clicks for every section pair. Each content panel resolves its own input field or returns no field, terminating native parent delegation before it can recurse back through the hub.

Release verification does not replace a live client/server acceptance run: native permissions, current friend status delivery and actual movement should also be checked manually after installation.

The typography plan is recorded in button-groups.json. Navigation, toolbar/filter commands, table actions and footer groups use shared 16 px Alegreya Sans SC fonts, measured across every state caption in Regular and Bold. Heading groups use the same 16 px size in Bold, a 28 px band, compact fixed chevron slots and one shared outer frame without internal dividers. Group membership and baseline remain stable during hover, sorting and scrolling. Table cells retain full tooltips when their visible text is shortened. The mini-map and full-map rendering geometry are unchanged.

ALL WAYPOINTS updates

Table actions use 24 px buttons centered in 28 px rows, with 2 px of non-clickable space above and below. The shared all-waypoints.row-actions, tracked-targets.actions, surroundings.row-marks and monitoring.row-marks groups reserve all state captions in both font weights. Monitoring's Back to Waypointer, Refresh and count strip share monitoring.footer sizing and baseline, 8 px gaps, and Alegreya Sans SC; its title uses the same family's 16 px Bold role as the table headings.

All product text uses the bundled Chamomilo font pool. Table contents, ordinary labels, input fields and dropdown option lists use 16 px Alegreya Sans Regular/Bold, preserving the original case of names and editable text. Window/map titles use 18 px Alegreya Sans SC Bold; compact HUD roles use Alegreya Sans SC at their existing fitted sizes. Buttons retain their density-specific typography groups. Padded table cells use native array descendants, so scrolling translates the complete button and its spacers together. Native game tooltip rendering remains owned by Wurm.

Both surface maps layer received terrain over the downloaded server image. Every second, the client samples at most 121 tiles (five in each direction from the player's current tile), using Wurm's native map colours and actual terrain receipt. Only changed 16×16 patches receive new pixels and texture uploads. Up to 64 patches remain available during the current world session; unknown cells stay transparent, older patches are evicted, and disconnect, transfer and HUD replacement clear the cache. Observations outside the current live terrain range are labelled last observed. The underlying distant map still follows the configured publication refresh interval, and local changes appear after the server sends their terrain updates.

Manage catalogue membership does not add a waypoint. Track or animal Nav explicitly adds it; On/Off controls visibility separately. Previously added targets remain listed while disabled. Delete removes their UUID from the manager, retaining the catalogue record and received history for another explicit Track. Identical object names can represent different server IDs; the complete name and UUID remain available in hover text.

Background updates patch distances and data-age captions in existing cells, preserving row order and the visible target. Structural updates and explicit refreshes restore the visible UUID and its intra-row pixel offset. Distance sorting is applied on explicit Refresh/sort actions, so moving targets do not reshuffle the list each second. Dropdown selections remain drafts until Apply filters; Refresh retains applied filters. Closed fields and detached popup contents both enforce constant alpha 1.0f.

The top ALL WAYPOINTS toolbar groups Add and Refresh. On and active NAV use stable green face/underline highlights; hover retains the kit's bold warm caption. Delete acts immediately without a confirmation popup. Visible now means a loaded target; the hint describes the last coordinate update separately. Last seen means the target left the client stream and retains the received position age.

In all three surroundings sections, Unmark, Clear filtered and Clear all marks remove waypoint membership, including legacy static marks. Nearby marks follow the received object ID rather than a copied position. Movement and catalogue refreshes cannot re-add removed memberships. Counts include only the displayed object kind.

Filter choice popups show all choices without internal scrolling, splitting into columns on shorter screens.
