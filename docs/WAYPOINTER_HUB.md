# Waypointer hub and tracking

The main window owns selection, frame and native window lifecycle. Each section is a reusable content panel; switching sections preserves its current filters. Edit previews are cleared when leaving the waypoint editor. All global configuration preferences live in SETTINGS; record styles and list filters stay beside the records they affect.

Editor focus activates only the attached owning hub. Native `HeadsUpDisplay.setActiveWindow` registers its argument as a top-level component, so a child content panel must never be passed directly. Closing removes every owned HUD component, including cached panels promoted by older focus code and dropdowns registered in both native popup and component lists. Filter windows are disposed through their original HUD. Preview cleanup errors cannot prevent removal; unrelated windows and navigation remain active. The native lifecycle regression covers route/close, compass reopening, editor typing, chat-focus restoration, legacy orphan removal, auxiliary filters, failed preview cleanup and HUD replacement.

## Search

ALL WAYPOINTS has server, user, type and status selectors, with no + filter or - filter text rows. Other searchable sections retain both text filter rows with the same layout: heading above a single line containing the text field, Clear button and example. Each comma-separated fragment is a literal substring, not a regular expression. `horse, wolf` includes either name; `old, champion` excludes either fragment even when plus matches. Matching is case-insensitive. Surroundings also searches category, material, modifiers, deed state and IDs. Deed search covers the displayed deed, mayor and coordinates.

## Position states

Catalogue membership alone never adds a friend or managed object to ALL WAYPOINTS. Press Track in MY FRIENDS or MY VEHICLES AND ANIMALS, or explicitly add a nearby object as a waypoint, to include it. Position unknown/Pending entries remain outside ALL WAYPOINTS until that choice. Added targets may later have unknown positions without losing their place in the list.

Waypoint membership is persisted independently of On/Off. Disabling an added target hides its marker but retains the row. Delete in ALL WAYPOINTS removes membership and disables tracking immediately; catalogue refreshes and movement keep it outside the list until another explicit Track. Its catalogue entry and coordinate history remain available. When loading an older cache, enabled targets are retained as added while automatic disabled candidates stay outside the list.

| State | Meaning | Presentation |
| --- | --- | --- |
| Visible now | Coordinates received from a currently streamed target | Live marker and navigator follow movement |
| Last known position | Target left the stream; the previous coordinate was retained | A grey compass marker with the state and observation age; NAV goes to that saved place |
| Position unknown | Catalogue entry without coordinates, a friend on another server, or an expired position | No exact marker or NAV |
| Approximate direction | Native animal Find returned a relative sector and distance band | North-up search area; no invented point or exact NAV |

MY VEHICLES AND ANIMALS requests the vanilla Manage animals, carts/wagons and ships catalogues on first selection. Refresh requests them again; switching back preserves the catalogue without repeating requests. MY FRIENDS also refreshes on first selection. Its Online filter offers All, Online and Offline, follows native server presence, combines with both text filters and survives refreshes and section switches. All includes unknown status; Online includes friends on other servers. Both views use 32 px table rows with fixed branded Bold headings, shared column geometry and compact grouped actions. All headings cycle ascending, descending and source order; missing distances/timestamps stay last in both directions. Background revisions preserve existing row order, the visible UUID and its intra-row pixel offset. Bearing/range uncertainty is retained in semantic hints rather than embedding a plot in every row. Native BML backslashes are literal text, including the ascending Name /\ heading. Owned recognized responses populate Waypointer; manual or unknown forms remain native. Direction is available only when the native animal catalogue supplies a Find action and a selectable object ID. Rows without an ID remain readable but cannot be tracked. The gateway sends only close or find responses; it never invokes care, brand, tame, transfer, hitch, lock or other ownership actions.

Readings use the character's pose at the Find request. Up to four readings no older than one minute are intersected; the result remains an approximation because animals can move. Bearings expire after two minutes; the earlier exact last coordinate is restored when available, otherwise the position becomes unknown. Last coordinates are retained for 90 days by default, configurable in SETTINGS. Clear last seen removes the saved coordinate; Untrack removes waypoint membership while preserving its history. Refresh can repopulate a cleared coordinate when the client receives the target again.

MY FRIENDS uses vanilla friendship/status data already received by the client. The mod obtains coordinates only when Wurm streams that player locally. An online status is not a global location service. Deleted friends leave this view after the next friend-list update; a saved tracked record can remain in ALL WAYPOINTS.

## Settings and persistence

The hub enforces the minimum width required by every section at the selected language and font size. Its tables have only vertical scrollbars, with headings fixed above the scrolling body. Monitoring uses whole rows and an 8 px minimum gap before its footer; active Mark/Clear actions stay green until cleared. MOBS AROUND uses Mark, Name, Condition, Hostility, Unique, Deed and Distance. Condition is the creature modifier; Hostility is the received native attitude. The unavailable Traits column is removed. All column headers cycle ascending, descending and original arrival order; the separate sort dropdown and Apply action are removed.

Surroundings actions occupy a single footer row. The square ADD TO MONITOR action beside the fixed table heading opens the current filtered section in the compact companion. Its caption is centered on three rows (ADD / TO / MONITOR). The monitor action retains Low density spacing with uppercase captions per explicit user override. The hub selectors form one Low density group with equal widths, 56 px heights and shared 24 px captions. ALL WAYPOINTS actions form a High density group with 32 px heights, shared 20 px captions and individual widths measured in both regular and bold. Each click replaces its current filter; there is no watch-preset collection or Clear watches action. All Waypointer controls use Chamomilo Interface Kit 0.4.4 and its regular/bold Alegreya Sans and Alegreya Sans SC fonts from canonical updater 1.1.0. The complete reviewed module supplies the sole embedded SDK copy, verified during distribution builds.

Language codes are `en`, `pt-BR`, `de`, `ru`. Names received from the server are not translated. A settings draft applies only after the full draft validates and the background save succeeds. Comments, unrelated properties and a `.bak` copy are preserved. Storage path changes take effect after restarting the client. Existing settings and existing waypoints remain compatible.

The dynamic target file is `wurm-waypointer-data/dynamic-targets.wpt`. Its records are qualified by character and endpoint. Restart converts previously live coordinates to last known coordinates. A failed cache load disables writes to preserve the unread file and reports the problem in the catalogue view; a failed save is reported and retried. Main static waypoint storage remains separate.

## Architecture and verification

- `core`: tracking state, bounded BML parser, direction geometry, filters, localization and settings schema. No native rendering or network requests.
- `client-wurm`: Manage transport and request ownership/timing, vanilla friend adapter, streaming integration, background storage/settings adapters and hub panels.
- `render-wurm`: shared button/frame resources and navigation projection. Last known and exact positions use distinct presentations; bearings never enter exact navigation.

Tests cover valid/unknown/truncated native forms, unsolicited replies, owner mismatches, fresh question IDs, manual Manage cancellation, timeouts, failed replies, substring precedence, restart/account/endpoint isolation and comment-preserving configuration saves. The native UI probe uses production Wurm layout/input components with GPU drawing replaced by an offscreen renderer and emits previews for all seven views in all four languages. It also checks keyboard-focus queries and native selector clicks for every section pair. Each content panel resolves its own input field or returns no field, terminating native parent delegation before it can recurse back through the hub.

Release verification does not replace a live client/server acceptance run: native permissions, current friend status delivery and actual movement should also be checked manually after installation.

The typography plan is recorded in `button-groups.json`. `hub.navigation` coordinates every left selector, retaining Low density spacing and fonts with uppercase captions per the user's explicit override of the default lowercase rule. `all-waypoints.commands` reserves On/Off, Nav/Stop and editor actions before fitting; `all-waypoints.footer` coordinates the complete bottom row separately. Table headings use the separate `all-waypoints.headers`, `surroundings.headers`, `tracked-targets.headers` and `monitoring.headers` groups through `WaypointerTableHeader`: 18 px Alegreya Sans SC Bold at rest and hover, one common ink baseline, a 32 px band, 6 px caption inset and a fixed 16 px glyph slot. The updated canonical TABLE-HEADERS.md requires one outer frame painted once with UiPainter.frame and no internal vertical separators in any table heading band. Non-sortable headings reserve the same slot but show no glyph. Existing explicitly requested three-state sorting is retained in Around and tracking views. `surroundings.filters` includes Condition/Unique/Deed/Layer/Mark, with the equivalent category/material filters in other sections. It reserves all single-choice and count states at one readable size, shortening overflowing display captions while retaining the full native label and selection hint. `surroundings.footer` and `settings.footer` coordinate their complete action rows. `WaypointerButtonGroup` selects common supported fonts, unions ink across every caption and both weights, and gives native wrappers shared caption metrics without allocating separate atlases. Responsive layout changes widths without fitting captions independently. `surroundings.monitor-primary` is a separate singleton: 144 x 144 px, Low density, three rows and independent ink-based fitting with harmonious outer space.

## ALL WAYPOINTS updates

Table actions use 28 px buttons centered in 32 px rows, with 2 px of non-clickable space above and below. The shared `all-waypoints.row-actions`, `tracked-targets.actions`, `surroundings.row-marks` and `monitoring.row-marks` groups reserve all state captions in both font weights. Monitoring's Back to Waypointer, Refresh and count strip share `monitoring.footer` sizing and baseline, 8 px gaps, and Alegreya Sans SC; its title uses the same family's 18 px Bold role as the table headings.

All product text uses the bundled Chamomilo font pool. Table contents, ordinary labels, input fields and dropdown option lists use 16 px Alegreya Sans Regular/Bold, preserving the original case of names and editable text. Window/map titles use 18 px Alegreya Sans SC Bold; compact HUD roles use Alegreya Sans SC at their existing fitted sizes. Buttons retain their density-specific typography groups. Padded table cells use native array descendants, so scrolling translates the complete button and its spacers together. Native game tooltip rendering remains owned by Wurm.

Both surface maps layer received terrain over the downloaded server image. Every second, the client samples at most 121 tiles (five in each direction from the player's current tile), using Wurm's native map colours and actual terrain receipt. Only changed 16×16 patches receive new pixels and texture uploads. Up to 64 patches remain available during the current world session; unknown cells stay transparent, older patches are evicted, and disconnect, transfer and HUD replacement clear the cache. Observations outside the current live terrain range are labelled last observed. The underlying distant map still follows the configured publication refresh interval, and local changes appear after the server sends their terrain updates.

Manage and friend catalogue membership does not add a waypoint. Track explicitly adds it; On/Off controls visibility separately. Previously added targets remain listed while disabled. Delete removes their UUID from the manager, retaining the catalogue record and received history for another explicit Track. Identical object names can represent different server IDs; the complete name and UUID remain available in hover text.

Background updates patch distances and data-age captions in existing cells, preserving row order and the visible target. Structural updates and explicit refreshes restore the visible UUID and its intra-row pixel offset. Distance sorting is applied on explicit Refresh/sort actions, so moving targets do not reshuffle the list each second. Dropdown selections remain drafts until Apply filters; Refresh retains applied filters. Closed fields and detached popup contents both enforce constant alpha 1.0f.

The top ALL WAYPOINTS toolbar groups Add and Refresh. On and active NAV use stable green face/underline highlights; hover retains the kit's bold warm caption. Delete acts immediately without a confirmation popup. Visible now means a loaded target; the hint describes the last coordinate update separately. Last seen means the target left the client stream and retains the received position age.

In all three surroundings sections, Unmark, Clear filtered and Clear all marks remove waypoint membership, including legacy static marks. Nearby marks follow the received object ID rather than a copied position. Movement and catalogue refreshes cannot re-add removed memberships. Counts include only the displayed object kind.

Filter choice popups show all choices without internal scrolling, splitting into columns on shorter screens. Each choice has one 32 px row, separate 32 px check-square hit targets and 6 px horizontal gaps. Choice captions, clear selection and Done share `surroundings.filter-choices` metrics; square controls use the kit's CHECK/MAXIMIZE glyphs and fixed alpha. Selection applies immediately through either the square or caption. Standard dropdowns likewise show the complete option grid, retaining native outside-click dismissal and fixed-alpha SDK field rendering. Native checks select the last option in every checkbox filter and manager/settings dropdown, including 80 choices and a 480 px viewport. Interactive headers and repeated Mark/Unmark actions have separate explicit groups, reserving all state variants; header and body boundaries use the same final widths through the SDK resize API. CONTAINERS AROUND and OBJECTS AND ITEMS AROUND omit the complete Short name filter row and its draft state.
